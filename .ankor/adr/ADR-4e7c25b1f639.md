title: Les claims vivent dans des refs git, jamais dans les fichiers
created: 2026-07-27T09:15:00Z
status: accepted
scope:
  - crates/ankor-cli/**
constraint: |
  Un claim n'est jamais écrit dans un fichier de tâche. Il vit dans
  refs/ankor/claims/<task-id>, un ref par tâche. Ankor ne commite jamais,
  sauf accept, qui produit le commit signé de ratification.
schema: 1
version: 1
---

Les deux plans sont orthogonaux : l'état durable est répliqué et versionné, la
coordination est éphémère et jetable. Écrire un claim dans le fichier
produirait un diff git à chaque prise de tâche — exactement le bruit que la
séparation existe pour éviter.

Un ref par tâche et non un ref global : deux agents qui prennent deux tâches
différentes ne doivent jamais se disputer la même mise à jour de ref. Le
compare-and-swap de git arbitre alors exactement le conflit qui compte.
