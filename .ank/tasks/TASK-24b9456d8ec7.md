model.rs states it as settled fact:

    Accepted -> Superseded is the only legal write on an accepted ADR,
    performed by the accept of the ADR that replaces it.

accept does not do it. It promotes the proposed ADR, writes ratified, commits signed, and never touches the target. The transition the model declares legal has no code behind it, so the only way to mark an ADR superseded is to open the file -- which is the practice this whole line of work exists to end.

Two writes in one operation, and the order matters for the same reason it matters in done: durable state before the commit. The ratification commit is authoritative as soon as it exists, so it must not exist over a corpus that check would call broken.

Refusing a target that is not accepted is not pedantry. Superseding a proposal is meaningless -- nothing was ever binding -- and the caller almost certainly meant a different identifier.
