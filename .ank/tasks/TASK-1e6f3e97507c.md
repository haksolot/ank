Two edits by hand this session, both in .ank/, both because no command exists.

TASK-3109a736c255 needed a blocked_by added after it was filed. TASK-84238e3e179d needed its scope corrected before it could be claimed at all -- ten struct literals across six files stop compiling the moment a field is added to Task or Adr, and the scope named neither them nor commands.rs, where the criterion's own 'ank new writes it' lives.

Both were legitimate. Neither was checkable by anything, which is the same argument TASK-1f4f7b57039b made for attest: an edit performed by hand is indistinguishable, in the resulting file, from any other edit performed by hand. A verb can guarantee that the fields it did not name come back byte-identical. A human with an editor cannot.

**It became urgent rather than merely untidy.** ADR-01b6dd05f0db closed .ank/ to direct reads and writes by an agent, and the PreToolUse hook that enforces it is checked in. It did not fire this session only because Claude Code loads hooks at startup and the file was born mid-session. From the next session on, an agent that needs to add a blocked_by is refused by the hook and has no command to fall back on -- the gap stops being a rough edge and becomes a dead end.

**Human surface, and the reasoning is TASK-bc214fd815b2's, already written down.** Adding a blocker to a task that already exists is a different act from creating one: it is a change to a plan that is not yours. ADR-3859eb46bdc3 freezes the agent surface at eight and sends new functionality here, and human.rs can grow freely, which is what makes that freeze sustainable.

**Add and remove, never replace.** A verb taking the whole list is a verb that silently drops what the caller forgot to repeat, and the round-trip guarantees nothing about intent. Naming what enters and what leaves is also what makes the log line worth reading afterwards.

**done_criteria is not on the list and must be refused loudly.** It is frozen by hash at claim, the anchor is held where the file's editor cannot reach it (ADR-6b3f19e08a24), and a verb that edited it would be offering to do the one thing the whole freeze exists to make visible. The refusal names ank release --reason instead, which is what a wrong criterion actually calls for.

**Scope under a live claim is the interesting case.** The claim record anchors the hash of the constraints applicable to the task's scope, so widening or narrowing that scope can change which ADRs bind the work in progress -- and done already warns when that hash has moved. Refusing the edit would be wrong: a scope discovered to be false mid-task is exactly the situation that produced this task. Allowing it silently would be worse. It is allowed and it warns, naming the holder.
