Required by ADR-bcf222a31525: the completion ref records the current branch, and
its pruning is decided on the content of the task file as it appears on the
default branch. Neither resolving that branch nor the necessary git commands
existed.

A new task and not a reopening of TASK-c8637488773c, which is `done` (§3):
`config.rs` and `git.rs` are in its scope, but what is missing is not a defect in
its work — it is a need a later ADR created. Its proof stays intact.

`for-each-ref` and `merge-base` were not in the plumbing list allowed by
ADR-92b9cda9f6a9. ADR-b8884edcebe3 replaces it and replaces the closed list with
a criterion: the output must be stable by contract across git versions. The
absence of `for-each-ref` predated this task — the specification has required
`check` to prune orphan refs since revision c, and pruning without enumeration is
not implementable.

The criterion sits at the level of the function and the plumbing, not the binary:
no command exposes the default branch yet. `accept` is the first to depend on it,
and it is TASK-a7b8c9d0e1f2 that must check through the binary the code 9 with no
resolvable branch and the code 7 off the default branch. The rule "a criterion
that talks about the binary is tested through the binary" is respected by not
making this one talk about the binary.

`refs/remotes/origin/HEAD` does not necessarily exist after a clone, depending on
the command used, and does not exist at all at level 0. The case "neither source
answers" is therefore the nominal case of a local repository with no remote, not
an oddity: that is why it has its own message rather than a fallback to `main`.
