§3 allows exactly one write to a task after `done`, and it is an addition to
the `proof` list. Nothing implements it. `done` wants a live claim and a task
that is not finished; `claim` refuses one that is. The only permitted write on
a finished entity has no command.

It has been done twice by hand instead. Commit 98dbf3b appended a `ci://` entry
to TASK-a99baa078994, and TASK-c2fae25adc66 appended one to TASK-a1b2c3d4e5f6 --
both by opening the file, bumping `version`, and writing the log line manually.
Both were correct. Neither was checkable by anything.

That is the argument. An append performed by hand is indistinguishable, in the
file, from a substitution performed by hand: the append-only rule of §3 is a
sentence in the specification and nothing enforces or even observes it. A verb
that appends can guarantee the entries already present come back byte-identical.
A human with an editor cannot, and ADR-6b3f19e08a24's answer -- anchor the
freeze in an artifact the editor does not control -- has nothing to anchor here.

**Human side, and that is not a consolation prize.** ADR-2f8a61c04b7d freezes
the agent surface at seven verbs and sends new functionality to the human side
or into the format. `human.rs` says the same from the other direction: it can
grow freely, and that is what makes the freeze sustainable. Adding a proof to a
task somebody else finished is not loop work, and an agent that could re-open
its own completed tasks is an agent that can grade itself twice.

Refusing a task that is not `done` matters as much as the append: the verb that
applies there is `ank done`, and the refusal has to say so.
