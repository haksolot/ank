At the hang: ank wchan=anon_pipe_write; child is git hash-object --stdin-paths, wchan=anon_pipe_write, wchar=64944 (=1584*41, identical to the field report), rchar=73177. Arithmetic: each path is 41 bytes in and a 41-byte hash out. The child blocks once its stdout pipe is full (64944 bytes, 1584 hashes, of the 65536 a Linux pipe holds), having consumed about as much input; the parent then blocks once the 64 KiB stdin pipe fills behind it. So write_all-then-read deadlocks when the input exceeds about 2*65536 bytes: 131072/41 = 3197 paths predicted, 3200 measured (the .ank paths are a few bytes longer). cat-file --batch-check (46 bytes in, 48 out per path) runs first and did not hang at this N, but has the same shape.
