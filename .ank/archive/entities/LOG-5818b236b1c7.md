 is gone and page() takes nothing off the body: a frontmatter is as long as it is, and a block of standing chrome would have had to be short enough to leave the document room -- the one that could not fit would have been silently cut. So pane_rows() is now block rows then prose rows, one list under one offset.

The body panel therefore has a cursor, and it is the free Focus::Body slot of the existing cursors array: no App field was added, which keeps out of the glyphs agent's perimeter. Focus::holds_rows() is unchanged and still false for the body -- what it decides is everything written for a listing (the digit that names a row, the tap that selects one, the shared clamp), and a document answers none of that. The cursor is kept inside the window by App::clamp_body() instead, and selected_id(Focus::Body) answers with whatever the row under it names, so Command::Open needed no new road: Enter on a constraint row of the block opens it through the same open_selected() a listing goes through.

The marker only ever lands on rows this crate composed. A prose row is drawn with the file's own characters and no left margin, which is what keeps 'the content is what show printed' true on the screen as well as in Detail::content.

Two comments outside my assigned functions were made false by this and I fixed them rather than leaving them lying: Focus::holds_rows()'s doc, and the doc on the App::cursors field (~line 401), which said the body's slot is never read. The cursors field doc is inside the glyphs agent's perimeter -- a doc comment, no code -- and this is the notice that it was touched.

model.rs: declared_scopes() no longer has a walk of its own. frontmatter() is that walk generalised to every field, declared_scopes() is it asked for 'scope', and prose() is the other half of the same fence split. Nothing is parsed out of .ank/: what the walk returns are borrowed halves of the content the CLI printed.
