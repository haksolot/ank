## Context

`accept` runs on the default branch only (ADR-6d8736c04cfa), and the default
branch of a protected repository takes no direct push. So every ratification
is the eight-line recipe of `docs/ratifying.md`: accept, branch at the
ratification commit, reset the default branch, push, open a pull request
naming the branch, merge with a merge commit, pull. Each line has a way to go
wrong that the page documents at length, and a squash or a rebase at the end
silently or loudly breaks the anchor.

"accept writes a commit and stops; it never pushes" is stated by that page, not
by an ADR.

## Decision

1. `ank accept` takes one or more ids. Each still produces its own commit with
   the subject `ratify <id>`, which is the anchor.
2. **`ank accept <id>... --pr` carries them to a pull request.** After the
   commits it creates `ratify/<first id>` at the last of them, resets the local
   default branch to its upstream, pushes the branch, and opens a pull request
   against the default branch through `gh`. It prints the merge command, `gh pr
   merge ratify/<id> --merge`, and **never merges**: the merge commit, and the
   review before it, stay a human's.
3. Without `--pr`, `accept` is unchanged: it commits and pushes nothing.
4. `--pr` checks its prerequisites before the first commit: an upstream for the
   default branch, a working tree with nothing `accept`'s `git add` would sweep
   in besides the entities, and `gh` present and authenticated. Any missing is
   exit 9 (or 7 for the tree), with nothing written.
5. A failure after the commits (push refused, `gh` error) leaves the commits on
   the `ratify/` branch and the default branch reset, and names the command
   that finishes the job.

## Consequences

- Ratifying on a protected default branch is one command and one merge.
- `docs/ratifying.md` keeps the manual recipe as what `--pr` does, step by
  step, for a repository without `gh`.
- `--pr` is the second verb, after `update`, whose network act is the point of
  the call (SPEC-15a56aeedcfd: asked for, so paid for).

## Rejected alternatives

- Merging as well: removes the last human look at the ratification before it
  binds, and the merge method is where the anchor is won or lost.
- Making the pull request the default: changes what a plain `accept` does on
  every repository, including unprotected ones that need none.
