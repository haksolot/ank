THE GATE. App::run split into App::propose (composes the argv, asks Ank::spelling for the line, and stops) and App::confirmed (the only caller of Ank::act in this crate). Between them sits a private Pending {verb, args, shown}, frozen at compose time and never recomposed: the identifier came from whichever panel had focus, so resolving the target again on the way out would land a verb on whatever the cursor had reached by then. keys::confirming answers one key -- 'y', bare, no modifier -- and EVERY other key dismisses. That way round on purpose: 'no keystroke that dismisses runs anything' is then a claim about the whole keyboard rather than about a list somebody has to keep complete, and a held key, a paste and a stray arrow all reach the same place. 'q' over a confirmation declines and does NOT quit -- a key that both refused a write and took the screen away would be the one keystroke whose effect nobody could read afterwards.

WHERE IT IS DRAWN, and this is the seam for dd97. It is three lines in note_lines(), the full-width unbordered band that already holds the prompt and whatever the reader is being told. App::arrange is UNTOUCHED: no new rectangle, no new panel, nothing to reflow. So the one-column branch dd97 adds inherits the confirmation for free, and hit-testing has one fewer region to resolve. The band is Constraint::Length(note_lines().len()) and that is safe recursion-wise -- note_lines reads self.width() and never calls page(), so it does not reach arrange() the way bb43's counts trap does. It wraps rather than cutting, asserted at twenty columns as well as eighty: an argv shown three quarters of the way through reads as the whole of it.

WHAT dd97 MUST NOT BREAK. The confirmation is MODAL -- while one is waiting, press() answers it before anything else, so no key moves a cursor, changes focus, opens a document or reopens the prompt. A mouse event has to go through the same gate: a tap while a command is on the screen must dismiss it, never resolve to a panel, or the argv on the screen stops being the argv that runs. That is the property the whole thing rests on and it is the one a second input road can silently take away.

ONE SPELLING, composed once. Ank::argv builds the argv (address flags, verb, args, --json) and Ank::spelling quotes it into the line a shell would have to type; quoted() is POSIX single-quoting, so a log message or a scope glob with spaces is one argument on the screen as it is one argument to the child. Ran.shown and all three Failed variants now carry that same string (their field is 'shown', not 'args'), so the confirmation, the chrome over an answer and the name in a refusal cannot disagree. The program word is 'ank' rather than the resolved absolute path, because the point of the line is that it is checkable against what a person could have typed.

MADE MECHANICAL rather than asserted in prose: tests/dependencies.rs now counts 'ank.act(' across src/ (ank.rs exempt, it is where the gate is defined and driven) and fails on anything but one call, in view.rs. A second call site would be a second road to a spawn, and it would be a road with no confirmation on it.
