 crates/ank-tui/tests/config.rs failed on ubuntu and macos, and cargo stops at the first failing test binary, so the ank-tui suites after it never ran. Cause, read off the frame CI printed (2 ENTITIES all 3, 6 in the corpus, TASK-3cf1 on the listing): the test took the first id find returned that was not there before, and new now also writes a LOG entry, whose id sorts before TASK-, so it waited for a log entry to become a row. The ank-tui suites are all cfg(unix) (0 tests on Windows) and cargo has no Linux linker here, so I read every one of them for creation-record sensitivity instead of running them. 2 ENTITIES and ENTITIES all N count rows, which log entries never are, so they are unaffected. Fixed, outside this task's declared scope, on the orchestrator's instruction to make the branch green: config.rs keeps TASK- ids; opening.rs and wheel.rs count the (N in the corpus) total as entities plus their creation records (CROWD+4, 4); ordering.rs drops LOG- ids from find order before comparing against rows; log.rs's no-section test needs an entity with no entries, which new can no longer make, so it stamps the seeded ADR under ADR-7000000000ad the way Repo::crowded stamps. cargo check --tests --target x86_64-unknown-linux-gnu -p ank-tui finishes clean.
