 Three of the four -- cli.rs, commands.rs, human.rs -- spelled a tab and a carriage return through the catch-all below 0x20, as \u0009 and \u000d. The fourth, context.rs, spelled them \t and \r. Both are valid JSON and they are not the same bytes. The module keeps the majority form, so context is the one document whose bytes can differ, and only for a value carrying a tab or a carriage return -- no fixture in the corpus carries either, so no golden moves. Pinned instead by a unit test in json.rs, one_spelling_for_every_control_character, since a behaviour no golden exercises is a behaviour nothing holds still.
