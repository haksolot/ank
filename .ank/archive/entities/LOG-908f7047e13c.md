Done: Repo carries corpus and worktree as two fields, --worktree names the second, and the 83 call sites of the old single root were assigned one by one against ADR-9e56318631f3. Ten went to the work tree: the hint that names an absolute path back relative, the commit: proof lookup in done and in attest, the HEAD and scope hash done anchors, the verifier working directory, the two tracked-file walks that confront a scope, and the two reachability questions that need history about the code. Eight new integration tests drive the binary with both flags, written as pairs so that "the flag moved it" is established and not asserted: the anchored run beside the same run without it. The degenerate case is pinned twice, once by a test comparing --worktree <corpus> with no flag byte for byte, and once by the goldens: help.json gained 22 --worktree entries and help-verb.json one, and with those 23 fragments removed both documents are byte-identical to what HEAD carries. Contract version does not move, which is what ADR-6fd69efb629c permits: a document may gain within a version.

One decision the ADR left implicit, taken here and worth naming. claim::complete records the commit and branch it was written from, and with two roots that is ambiguous. It stays the corpus: the record is the content of a ref, ADR-9e56318631f3 assigns refs/ank/* to the corpus, and the pruning that reads it is a question about the corpus reaching its default branch. A fixture caught it, since a corpus with no commit has nothing to record.

So the specification is revised by writing a new document that replaces the old one and waits for a human to ratify it, which is a second entity in the ratification queue per document and not an edit.
