## Context

ADR-b8884edcebe3 says git is a hard dependency and the version is "checked at
startup". The code took it literally: `cli.rs` routes every verb but `help`,
`config` and `--version` through `startup()`, which calls `git::ensure_usable()`
— a version check and a `rev-parse --show-toplevel`. Both are hard code 9.

The consequence is not the one the constraint intended. `ank show`, `ank find`,
`ank graph`, `ank scope`, `ank new`, `ank amend` and the whole formal half of
`ank check` — parse, byte-for-byte round-trip, `blocked_by` references, glob
validity, filename against id — need no ref, no commit and no branch. They refuse
anyway, because of a gate that stands in front of the dispatch rather than in
front of the operation.

That contradicts what the project says about itself everywhere else. The format
is the specification and the CLI is a reference implementation of it rather than
a gatekeeper (`docs/format.md`), `crates/ank-core/tests/golden/` is published as
a suite third parties can run, and the licence section of the specification takes
care to state that a `.ank/` corpus is not a derivative work. A binary that
cannot validate a corpus unless that corpus sits in a git repository makes all
three claims smaller than they read.

## What does not change

Everything the replaced ADR was actually protecting. There is still exactly one
claim mechanism, and it is still git refs; there is still no file-lock fallback,
and none is contemplated. The compare-and-swap that arbitrates two agents is the
one git already guarantees, server-side at push time, and no other backend gives
that property — a second one would give a weaker guarantee while looking
equivalent, which is worse than not having it.

The distinction this ADR draws is not between git and something else. It is
between **coordinating**, which requires an arbiter, and **reading a corpus**,
which requires a parser. The replaced constraint collapsed the two.

## Two defects in the enumeration, fixed while it is open

`constraint` is locked on an accepted ADR, so replacement is the only route to
correct it (section 3), and the occasion is worth using twice over.

First, the enumeration had fallen behind the code. `git.rs` has been calling
`rev-list` since the ratification walk was written, plus `config`, `push`,
`fetch` and `ls-remote` for level 1 — none of them listed. The list said eight
commands where the binary used thirteen.

Second, "never porcelain" was already false, and silently so: `accept` runs `git
add` and `git commit -S`, which are porcelain by any definition. The exception is
legitimate — the specification argues it in section 12, and producing a signed
commit through plumbing would be a cryptographic project for an equivalent
result — but an exception that lives only in a source comment is an exception a
reader of the constraint cannot know about. It is named here.

`diff-tree` is listed although nothing calls it yet. It is what rename detection
on a dead scope needs, it meets the criterion the replaced ADR established, and
listing it now is cheaper than a supersession later. The criterion is what
governs; the enumeration is its application, as ADR-b8884edcebe3 already settled.

## Rejected

**A `--no-git` flag.** It would make the caller declare what the verb already
knows. A verb either needs an arbiter or does not, and that is a property of the
verb, not of the invocation.

**Degrading the coordinating verbs too.** `claim` without an arbiter would
succeed and guarantee nothing, which is the one failure mode the coordination
plane exists to prevent. Those verbs keep exiting 9 with the exact command.

## Consequences

`check` grows a shape it did not have: two halves, one of which can be absent.
The line saying the coordination half was skipped is not optional — a check that
silently examines less than it did is how a corpus passes a gate that stopped
looking.

Repository resolution stops being a `rev-parse`. Walking up for `.ank/` is what
the corpus enumeration already does, so this removes a second way of answering
the same question rather than adding one.
