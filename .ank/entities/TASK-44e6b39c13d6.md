ci.yml:223 selects `startswith("done with no test proof")`. human.rs:2168 emits
a second wording for a task that carries a test proof a caller typed:
`done with no attested test proof: 'test:999' was submitted, not attested`.
That task is never selected, so the pipeline never anchors it, and check keeps
reporting it. Measured in a scratch corpus during the 2026-09-19 doc audit.

Matching on prose is the underlying weakness; a stable finding kind in
`check --json` would be the durable fix but is a contract change (ADR-6fd6):
if the diagnosis leads there, release and say so rather than widening this.
