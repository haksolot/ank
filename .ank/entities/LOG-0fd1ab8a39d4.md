 bucket/ank.json is generated by one heredoc in publish-scoop.yml; a release runs it for the new tag and commits the result, and every other run runs it for the version the committed manifest already claims and asserts git diff is empty. So the file is compared with the derivation of its own version on every pull request rather than only at the next tag. Measured on this tree by extracting that step verbatim out of the workflow YAML and running it against the real v0.2.0 release: it reproduces the committed bucket/ank.json byte for byte, the hash it reads out of ank-0.2.0-x86_64-pc-windows-msvc.zip.sha256 equals sha256 of the downloaded zip (4820e561...d8f47), and three falsifications go red -- a hand-typed hash that is committed, a url pointing at v0.1.3, and a .sha256 asset replaced by an HTML error page, which the 64-hex guard names rather than letting scoop report it later as a bad download.
