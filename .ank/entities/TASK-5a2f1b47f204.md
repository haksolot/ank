`npx skills add haksolot/ank` is what `skill/SKILL.md` already teaches, and it
serves several agents rather than one, which is why ADR-5fbd99bf6fd5's offer
routes through it instead of the installer learning where each agent keeps its
skills. There will be more agents than Claude Code, and an installer that knows
their directory layouts is an installer that goes stale silently.

**The last clause of the criterion is the one that matters.** An offer bolted on
after a working install is a new way for a working install to be reported broken:
`npx` fails behind a proxy, the registry is down, the network dies between two
steps. ADR-5fbd99bf6fd5 states the rule, and the criterion asks for it to be
*falsified* rather than reviewed -- make the step fail on purpose, on all three
platforms, and show the installer still exits zero with the binary in place.
That is the test that would have caught it, and the one that would not have
been written by reading the code.

**Reading the answer is where the platforms diverge.** POSIX `sh` under
`curl | sh` must open `/dev/tty`, since standard input is the script. PowerShell
under `irm | iex` has the same problem and a different answer. This is
OS-dependent behaviour in the sense CLAUDE.md means it, so it is not verified
until it has run on the three.
