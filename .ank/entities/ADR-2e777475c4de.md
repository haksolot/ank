## Context

GitHub #791 section 3. ADR-964be4d940b2 made signing a regime the corpus is in, not a precondition of ratifying: accept never refuses for want of a key. That is right as the default and leaves no way for a repository to say that an unsigned ratification must not happen.

## Decision

An opt-in key. Under it accept refuses on state, the configuration and the key at hand, never on identity, so it stays within the rule that the CLI refuses on state. This amends ADR-964be4d940b2 in one clause: "it never refuses for want of a signing key" holds unless the repository has declared require_signature. Writing ratify.* is the act config:permissions under the roles decision proposed beside this one.

## Consequences

Turning it on in a corpus that holds unsigned ratifications makes each of them a fault; the repair is accept --reanchor by a holder of a declared key. Refusing true with no declared key keeps the configuration from naming a regime nobody can satisfy.
