The maintainer of this repository works the backlog in parallel: several agents
launched through herdr, a terminal multiplexer for coding agents, each in its
own git worktree on a task whose scope collides with no other. What made that
work was learned the hard way and lives in one person's notes: export
`ANK_AGENT` and `TMPDIR` in the pane *before* starting the agent, or every
worker falls back to `<user>@<hostname>` and the claims cannot be told apart; an
agent told to wait for another task stops and reports instead of resuming, so it
needs a second prompt; removing the worktree is the reliable cleanup, closing
the pane with it. None of that reaches anyone else, and an agent orchestrating
for the first time meets each failure again.

**Why a sibling, and why herdr by name.** ADR-e4a5a8873fe3 makes the skill
system one skill per activity, and orchestration is an activity the five
existing siblings do not teach: ank-loop works the backlog as one agent, one
claim at a time. A tool-neutral orchestration skill was rejected: it would teach
runtimes nobody here has measured, and a skill teaches only what has been run.
Herdr is the runtime this project measured on, and the skill names it.

**Why the ank layer only.** Herdr ships its own skill and its CLI is the
authority on its syntax (0.9.1 when this was written). Copying commands would
make this skill drift at every herdr release, the drift ADR-e4a5a8873fe3 exists
to prevent between our own skills. What only ank can teach is the policy around
those commands: which tasks may run together, what each worker must carry, who
claims and who lands, and how a run ends.

**Why the orchestrator lands, and claims nothing.** `docs/multi-agent.md`
already sets the model: one agent, one tree, one identity; parallelism derived
from `blocked_by`; integration as a task. The orchestrator is not one of the
agents doing the work. It reads `ank context`, `ank graph` and `ank status`,
names the pairs whose scopes collide, launches the rest, and lands the branches
in sequence, because two merges racing each other leave intermediate commits
red and resolve their conflicts nowhere in particular. Since every sibling
directory is a valid method, `--method herdr` stays possible; ank-plan does not
set it, because the method names how a claimed task is executed, and nobody
executes a task as an orchestrator.

**Distribution.** Like every sibling: the binary carries it (ADR-e1d750884b82),
`ank skills --install` places it, and the description is the price every
session pays. It is kept to one narrow trigger, as herdr's own skill does.

**Accept stays out.** As in every skill, `accept` is described and never
invited: a run of agents ends with branches landed and proposed entities
waiting, never with a ratification.
