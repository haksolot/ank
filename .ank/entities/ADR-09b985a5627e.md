## Context

ADR-a1de673043b4 says a verb may read a peer's corpus and never write to it. It
does not say *which state* of the peer is read, and the implementation answers
by opening the peer's working tree. Measured on 2026-10-26 through the binary at
e04c0dad, in a scratch pair `api` (peers.web ../web) / `web` (peers.api ../api):

- With `api` checked out on an unmerged branch `work` where the blocking task
  was done, `ank claim` in `web` **succeeded**. With `api` back on `main`, the
  same claim was refused at exit 7.
- The same ADR read as `CONSTRAINTS (1 active)` or `PROPOSED (1, non-binding)`
  in `web` depending on the branch checked out in `api`, and an ADR draft never
  committed in `api` was listed in `web` as proposed.
- `ank check` in `web` was a **fault, exit 8** ("a task peer 'api' does not
  hold") with `api` present on `main`, and a **signal, exit 0** with `api` moved
  away. Having the sibling on disk answered worse than not having it.

In the multi-agent cycle this repository runs, the peer's checkout is another
agent's workspace. Its `git checkout` decided what bound this repository and
released work an unmerged change had not earned.

## Decision

A peer is read at its default branch, through git objects, exactly the base
`verify.rs` already measures against: the local default branch, then
`refs/remotes/origin/<branch>`. The working tree of the peer is never read. A
peer with neither ref is unreadable and degrades as today, one warning and the
local answer.

What "done" means across the boundary is then the same thing it means at home:
on the default branch. `status` already tells a task finished on a branch from
one on main; a peer edge now asks the question the same way.

**A peer task not yet on the default branch** is the orchestrator's normal case:
the pair is planned before either lands. `new --blocked-by TASK-x@api` accepts
it when a local branch of the peer holds it, and warns; it still refuses at exit
2 a task the peer holds nowhere, which is what catches a mistyped id. `claim`
treats the edge as held. `check` reports it as a signal and never as a fault,
because nobody in this repository can fix another repository's merge.

## Rejected

- **Keep the working tree and warn when the peer is off its default branch.**
  The answer would still depend on another agent's checkout; the warning names
  the hazard and leaves it live.
- **Refuse a peer reference until it is merged.** It forces the orchestrator to
  plan a contract change in two passes, one per merge.
