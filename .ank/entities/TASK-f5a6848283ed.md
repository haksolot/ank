TASK-bd8503f61993 and TASK-c04889b7f21f were closed on 2026-08-13 with the reason 'git 2.54.0.windows.1 accepts file:///C:/..., and the full suite is green at 2215a78 and at e1f0b18'. That statement is falsified on this machine and this git. Refiled with the measurement rather than reopened, because the closure carried a reason and a reason is answered by evidence.

Measured three times, at origin/main 37f6c4c with all work stashed:

1. cargo test --workspace: 155 passed, 1 failed, the failure being this test.
2. cargo test --test cli a_shallow_clone_cannot_explain, alone, twice: FAILED both times. Not load, which is what running it alone was for.
3. By hand, outside the harness and outside cargo, with MSYS path conversion disabled so the shell could not be the confound:

   MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL='*' git clone -q --depth 1 "file:///C:/.../urltest/src" ... -> exit 128
   fatal: '/C:/.../urltest/src' does not appear to be a git repository
   MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL='*' git clone -q --depth 1 "file://C:/.../urltest/src" ...  -> exit 0

git version 2.54.0.windows.1. The two forms differ by one slash. clone_of at crates/ank-cli/tests/cli.rs composes format!("file:///{}", path.replace('\\', "/").trim_start_matches('/')), which on a Windows absolute path yields the first form; git reads it back as the path /C:/... and refuses.

The test carries no cfg guard and no skip, so it runs on every platform and cannot have passed here. It is green on the Linux runner, which is why it landed: the platform rule this repository states -- OS-dependent behaviour is not verified until it has run on all three -- catches it, and here it is the test harness that is OS-dependent rather than the code under test.

Do not drop the shallow case on Windows to make this green. The third state of section 4, a history that cannot answer, has no other test.
