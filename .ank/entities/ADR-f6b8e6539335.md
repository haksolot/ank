## Why

Declaring a corpus for `ank watch` was entirely manual: copy the root commit out of `ank status --json`, hand-edit `watch.yml`, restart a running watcher (issue #806). The friction lands exactly when a corpus appears, and an undeclared corpus is quietly cold.

## What this changes, and what it keeps

ADR-24e21cb83793 stays whole: the watcher watches only what `watch.yml` declares, keyed on the root commit, and walks no filesystem looking for a corpus. What moves is who may write the declaration. Until now only the reader could, by hand. Two verbs now write it too, each about one checkout and only the one the caller is standing in:

- `ank init` declares the checkout it initialises, once that checkout has a root commit to be keyed on. A repository with no history has no identity, and init says so instead of inventing a key.
- `ank watch` started inside a checkout that carries a `.ank/` declares that checkout before reading the declaration. This is the walk up from the working directory that every verb already performs, and not a search: nothing above, beside or below is looked at, and `--list` and `--where` write nothing.

The declaration stays the only thing the watcher reads, so `nothing_walks_a_filesystem_looking_for_a_corpus` stays true as written.

A running watcher re-reads `watch.yml` when its bytes change, so the corpus `init` just declared is warmed without a restart. A declaration that stops resolving is a line on stderr, and the last one that resolved stays in force, which is how a failed fetch is already treated.

## The opt-out

`ANK_WATCH_DECLARE=off` makes both verbs write nothing. CI runners, containers and the test suite set it: a suite that runs `ank init` in hundreds of temporary repositories must never write into the real reader's `watch.yml`. The repository's `.cargo/config.toml` sets it for every `cargo test`.

## Writing someone else's file

`watch.yml` is the reader's file and may carry their comments. An entry is added by inserting one line, and the result is parsed back and compared with what was intended. Only when that comparison fails is the file rewritten whole from what was parsed.
