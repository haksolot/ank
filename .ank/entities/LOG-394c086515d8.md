Deriving from the presence of refs/ank/proof/<id> was rejected on measurement, not taste: maintain_proofs deletes that ref the moment the same (type, ref) pair appears in the file on the default branch, so a corpus that did nothing would change its answer the next time anyone ran check. A field that says what happened outlives the ref that carried it. No schema bump: the spec's own precedent at section 3 is that 'verified' did not earn one, because an older reader concluding 'absent' from its absence concludes the truth -- which is exactly the case here, while the log leaving the body earned the bump because a reader showed an empty history for a task that had one. Absent 'via' therefore means 'written before the distinction' and is read as anchoring, which is what keeps the twenty-one historical completions silent.
