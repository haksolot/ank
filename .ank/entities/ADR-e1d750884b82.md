## Context

The npm route exists for one workstation: the one whose firewall blocks a bare
executable and lets the registry through (SPEC-b156a5571668 §9). Measured on
2026-09-13: that route's documented second step, `npx skills add haksolot/ank`,
fetches from GitHub, which is the host that workstation cannot reach. The two
shell installers offer the skills after the binary is verified (TASK-5a2f1b47f204)
and each carries its own copy of the npx logic, node detection and fallback
lines, in two languages that cannot move a cursor the same way (LOG-bd099b). The
npm route has no moment to make the offer at all: `npm install -g` runs no
prompt, and a `postinstall` that wrote into a home directory would do it on every
CI runner, which is what ADR-5fbd99bf6fd5 forbids the installers.

The skills CLI accepts a local directory: `npx skills add <dir> --list` on this
tree, measured the same day, finds the six skills and names them with their
frontmatter. What was missing is a directory every route has. The binary already
reads `skill/SKILL.md` at build time for the revision it stamps into
`--version` (ADR-e4a5a8873fe3); reading the six files whole is the same read.

## The decision

One executable carries the teaching as it carries every surface
(ADR-1ea31c2f3c5a): the skills travel inside it, and a verb writes them out and
hands them to the ecosystem tool the specification already leans on. The verb
never prompts: a flag given is the answer, and the installers, which already
ask on a terminal and are silent to a pipe, keep the question and lose the
implementation.

This is a copy produced at release time and never committed, which is the form
ADR-8b3045cf11db allows; the source stays `skill/`, and a test holds the
embedded bytes to the tree's.

## Rejected

- A `postinstall` in the npm package. It runs with no terminal, so it either
  installs silently into every runner's home or does nothing; SPEC-b156 §9
  already rules out a postinstall that fetches, and this one would write.
- The wrapper passing the package's `skills/` path to the binary. It gives the
  npm route a source and leaves curl and PowerShell on the network fallback:
  two behaviours for one verb, sorted by how the binary arrived.
- The binary learning where each agent keeps its skills. Rejected by
  TASK-5a2f1b47f204 in the same words: an installer that knows agent layouts
  goes stale silently, and the skills CLI is maintained for exactly that.
- A verb that prompts. It would carry a second copy of the /dev/tty rule the
  installers already prove on three platforms, for one question.

## Consequences

`skills` joins the dispatch table, so the successor of SPEC-4b79c265ccb6 lists
it before the code lands: tests/skill.rs reads the surface out of the ratified
document and names any verb it does not find. build.rs reads six files instead
of one, install.sh and install.ps1 shrink by their npx blocks, and the npm
route reads `npm install -g @haksolot/ank` then `ank skills --install`, offline.
