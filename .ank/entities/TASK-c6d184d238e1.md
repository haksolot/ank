Issue #500 suggests `peers.<name>` accept a remote URL, so that `config.yml` is
portable without every reader writing an override. The user asked for it to be
studied rather than decided in the planning session.

What makes it a decision and not an implementation: a URL has to be cloned
somewhere and kept fresh, and only an explicit call reaches the network
(ADR-64f32c74a0f9). The daemon fetches nothing but `refs/ank/*`
(ADR-24e21cb83793). A peer read from a stale clone answers about a tree nobody
is looking at, and for a blocked_by edge (ADR-c23bef1cc93e) that decides whether
work is released. The per-user override (ADR-da2819aef598) already solves the
layout problem with no network at all; the study has to show what a URL adds
beyond it.

The product is a proposed ADR, not code. Leave the ADR proposed: accepting it is
a human act.
