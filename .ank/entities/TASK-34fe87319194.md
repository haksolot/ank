Found while working TASK-b896bfbc9c8b. A renewal that does not reach the remote keeps its local write (ADR-af533e7a3e03, ADR-aaee5307b34c), so the clone's ref and the remote's diverge. release then pushes the deletion with --force-with-lease on the local object; git refuses it client-side as rejected (stale info), ls-remote answers with the remote's (older, same holder) object, and claim::push reads Refused{holds:Some} as Cas::Lost with sync Pushed: delete_at reports nothing and the verb is silent while origin keeps the claim until its TTL. Measured on 2026-10-23 with a refusing pre-receive: log refused, then release from the same clone printed 'released' and no warning. The fix has to tell the caller's own earlier record from another holder's before deciding the deletion lost, without ever deleting another identity's claim.
