Raised by the independent review of PR #523 (branch `fix/status-ignored-dirs`).
`worktree_files` (`crates/ank-cli/src/git.rs`) now runs `git ls-files -z
--cached --others --exclude-standard`, and the deleted-file regression found by
the same review adds `git ls-files -z --deleted` beside it. Both are plumbing
by ADR-9307e5d214a7's own criterion -- `-z` prints one NUL-terminated relative
path per record and has done so since `-z` existed, a stable contract across
versions -- but `ls-files` is not in the `constraint` field the amended ADR
locks, so the corpus and the code disagree about which commands are admitted
for as long as this branch is open.

**Why an amendment and not an edit.** ADR-9307e5d214a7's `constraint` is
locked by its `accepted` status (section 3); ADR-9ee76b578257 is exactly the
mechanism for adding one command to an enumeration without retiring the
fourteen it already names or copying them into a new document.

**What this adds.** `ls-files`, admitted for two invocations only:
`ls-files -z --cached --others --exclude-standard` (every file this worktree's
git considers relevant, `worktree_files`) and `ls-files -z --deleted` (the
subset gone from disk without `git rm`, subtracted from the first so a
deleted-but-still-indexed path does not read as tracked). Nothing else about
the amended ADR changes: the claim mechanism, the plumbing-only rule for every
other command, and the `add`/`commit -S` exception all stand as written.

Left to the maintainer: ratification. This ADR is filed `proposed` and stays
that way; accepting it is `ank accept`'s act, not this branch's.
