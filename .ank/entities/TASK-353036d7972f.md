ADR-5bd8257dfeac decides it and gives the reason that is easy to miss: the one
surface the corpus offers for changing an entity is today a surface no agent can
use plainly. Changing one field means writing a program that patches a temporary
file and handing it to `ank` as `$EDITOR`, which was done in this repository on
ADR-9e56318631f3 and which works, and which pushes toward the direct file write
ADR-01b6dd05f0db asks agents not to perform.

**The refusals are the risky half, not the flags.** `edit.rs` already compares
the frozen fields against anchors the file's editor cannot reach, and the
temptation with a second entry point is to let it grow its own slightly
different set of refusals. The criterion asks for the same code and the same
sentence on both paths, tested side by side, because two paths that refuse
differently are two surfaces and §4 has one.

**What must not be built here.** No trace is written yet: that is
TASK order, and writing one from a surface whose refusals are not yet pinned
would record edits that should have been refused. And no field outside the
content of the kind addressed becomes writable: `author` is unchangeable
(ADR-3877fef1d662), `version` is the store's, `ratified` is `accept`'s, and a
flag that reached any of them would be a way around a freeze rather than a way
to type an edit.
