 claim: git::push_claim/fetch_claim became push_ref/fetch_ref, and claim.rs grew read_at/put_at/delete_at/sync_ref_from_remote with read/put/delete kept as claim-facing wrappers -- those do carry claims, so they do not lie. Record gained a Proof variant carrying a list of AttestedProof, each wrapping ank_core::Proof verbatim so the two sources cannot drift into two shapes of one thing; the list is what keeps append-only true on the ref side, since one address is the task. Both enumerations now walk the two namespaces once each rather than gaining a second walk: context::plane returns claims and proofs together with coordination() as a wrapper, and check's own coordination() does the same for the Record map it needs. A record whose state contradicts its namespace is a finding, never coerced -- read as the other kind it would present a held task as free or lose an attestation. The union in check is a single Vec over both sources feeding the no-proof fault, the weak-proof signal and the no-test-proof signal, which is the ADR's 'a signal that counts proofs counts both'. show prints a PROOFS section only when something is detached, and then lists both halves marked: the frontmatter above already carries the file's list byte for byte, so printing it twice on every done task would be noise, while the union exists only when a ref carries something. Pruning reuses the default-branch predicate and deletes only when every attestation in the record has an equivalent in the file, so a record holding an unmerged run survives. Two guards in the suite fired as designed and were answered rather than muted: --detached had to be classified in NOT_A_PATH, and listed_flags had to learn that a switch takes no value -- it was pushing a value at every flag, which for a switch would have measured a stray positional. Falsified by blinding both readers: all three binary tests fail. Filed TASK-ae77a9ee2964 for the specification half, which is outside this scope.
