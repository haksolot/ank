svg-term-cli ignores --profile. Measured rather than assumed: a profile path that does not exist produces the same bytes as a valid one, and two renders asked for opposite iTerm2 themes came back byte-identical. So Catppuccin is applied by substituting the eight colours svg-term actually emits -- background, foreground, three ANSI colours ank's output carries, the two the prompt uses, and the dim one. assets/demo/render.sh refuses when the base carries a colour it cannot map, because an unmapped colour survives into both files unchanged and is therefore right in one theme and wrong in the other, with nothing to say so.

gnupg is not installable on the recording machine without a password, so the demo repository signs with ssh. git has done that since 2.34 and .ank/allowed_signers already carries that format's file name. This mattered because a proposed decision is served as "non-binding" and the whole point of the recording is a constraint that binds -- the decisions had to be ratified for context to serve them the way the README claims.

One thing the rehearsal taught, and it changed the demo repository: a verifier declared in config.yml is not enough. The task must name it with --verify, or done asks for a --proof instead, and the recording would have shown a number being typed rather than a check being run. That is the opposite of what the last beat exists to show.

Everything is derived. setup.sh rebuilds the repository, play.sh plays the session, render.sh renders both themes -- so a retake is a re-run rather than a performance, and the .cast is committed beside them. 29.1 seconds against a ceiling of about forty.

Beyond the criterion, in the same file and at the maintainer's request: the two install commands moved above the fold, one fenced block each so each carries its own copy button, and the trailing comments removed. A comment after a command breaks it when the line is pasted, which is exactly how these two are meant to be used.
