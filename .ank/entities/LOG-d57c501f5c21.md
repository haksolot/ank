The store prefers the canonical copy over the previous entity layout because one entity in two places would show two versions of one task, and I copied that rule at first. It is wrong here. Nothing appends to the previous log directory any more, so it holds what was written before the move and the entities hold what came after, and the two sets are disjoint by construction. Preferring either hides half a history permanently, which is measurable: a task logged once before ank migrate runs loses every earlier line the moment the new entry lands. So about() unions them, orders the whole by timestamp with the identifier breaking ties, and drops a previous-layout line an entry already carries byte for byte, which closes the only window where the two can overlap, a migration interrupted between writing the entries and removing the file it read. Section 6 of the specification already said union with none counted twice, so this is the specification being implemented rather than a decision of mine.
