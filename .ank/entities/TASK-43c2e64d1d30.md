Found while measuring TASK-24ea4fbba3df, and recorded on it in LOG-0487a8d9b80e
and LOG-f21bd3d43750: `context` renews the held claim, and the renewal record is
stamped to the second. A renewal landing in the same second as the claim writes
an identical record, the push sends nothing, and `ank context` costs 10 git
processes; a renewal that changes the record costs 14.

So the difference between a renewal that says something and one that says
nothing is four processes, and the second kind is paid for in full: the ref is
rewritten and, at level 1, a push is started to send bytes the remote already
has. The measurement is already made; what is missing is the guard that skips
the write when the record is unchanged.

This is ADR-cc65f1388a71's invariance applied to a case nobody looked at, and
it is a cost in the claim code, which is why TASK-24ea4fbba3df, whose scope was
the tests, noted it and did not fix it.
