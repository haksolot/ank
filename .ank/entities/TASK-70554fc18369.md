## The defect

The test passes on windows-latest in 18 to 22s (eight green runs of main,
44956360201 to 44972253757). In run 44943400576 of main (4d26e8ee), attempt 1,
nextest killed it at 600.138s, and `.config/nextest.toml` already records one
pass at 327.623s against about 20s in three other runs. Thirty times the usual
duration is a wait that did not end, and the killed run printed nothing: no
case, no output, no survivor.

The three cases are a verifier that exits 3, one that sleeps 30s under a 1s
timeout, and a command that does not exist, each run with a second verifier
beating beside it. Linux and macOS have not shown it.

It cannot be reproduced on demand from here, so the criterion asks first for a
test that says what it was waiting on the next time it happens.
