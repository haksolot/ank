Issue #831. Measured on 1dbd58ff, release build, this repository (2 839 commits), GIT_TRACE at an absolute path:

    show <id>     440-520 ms, 4 git processes
    find <word>   400-600 ms, 5 git processes
    the walk alone, `git rev-list --full-history --format=... HEAD`: 1.7 MB out, about 225 ms

`git.rs::all_ratifications` memoises the walk for the process and loses it at exit. The set of `ratify <id>` commits reachable from a commit never changes, so the result is a pure function of HEAD's object name. ADR-f3d1dea65d84 asks that a cache state its key; it is stated in the criterion.

The precedent for a memo held in the index is TASK-be17972988d9 (the `verdict` table), and for the walk itself TASK-6e3f8f0049e9. An incremental walk of `<stored>..HEAD` when the stored commit is an ancestor is allowed and not required: the criterion asks only that an unchanged HEAD costs no walk.

Record the before and after process counts with `ank log` while holding the claim.
