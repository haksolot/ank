## What was measured

On 2026-10-28 the dev box sat at 100% CPU (load 5 on 4 cores) for five days.
The cause was four `ank tui` processes left behind by the `ank-tui` pty suite in
four different worktrees. Each had ppid 1, its cwd at `ank-it-<pid>/graphed-0 (deleted)`,
its binary deleted, and fds 0-2 on `/dev/pts/N (deleted)`. One thread per process
was in state R, with 4.4M involuntary context switches against 4 voluntary ones.
It made about 1.3M `read()` calls per second (counted from `syscr` in
`/proc/<pid>/task/<tid>/io` over one second), and `rchar` stood at 9 bytes since
start. So the reads returned 0, which is end of file, in a loop that never blocked.
The oldest process had used 4 days 18 hours of CPU.

## The chain

1. **The harness leaks the child.** `Live` in `crates/ank-tui/tests/terminal/mod.rs`
   kills its child only in `quit`, `ended` and the deadline branch of `exited`. It has
   no `Drop`, and `std::process::Child` does not kill on drop. A test that panics
   before it quits, for instance on a timeout in `until`, leaves `ank tui` running.
   When the test binary exits, the master side closes.
2. **No hangup reaches the child.** The harness gives the slave as stdio and takes no
   controlling terminal (no `setsid`, no `TIOCSCTTY`, on purpose, see the comment
   in `crates/ank-cli/tests/tui.rs`). When the master closes, the kernel sends no
   SIGHUP to anybody.
3. **The reader spins on end of file.** In crossterm 0.29 on Unix, `event::read()`
   does not return `Err` when the tty reads 0 bytes. It polls again, the fd is
   readable again (HUP), it reads 0 again, and so on. `term.rs::typing` returns
   only on `Err`, so `Wake::Broken` is never sent and the session never ends.

The orphans in the harness are what we saw. A person whose SSH connection drops
gets a SIGHUP as the session's controlling process, so the third link is mostly
hidden from people. It is not hidden from a reader started by a script, by a pane
manager, or by anything else that hands it a pty it is not the controlling
process of.

## Fixing both ends

- The harness: `impl Drop for Live` kills and then reaps the child when it is
  still running. A panicking test then leaves no process behind, whatever made
  it panic.
- The reader: a terminal that is gone ends the session. That means reading 0
  bytes from stdin, or POLLHUP on it, on Unix, and whatever the console reports
  on Windows when the pseudo-console is closed. The session then ends as it does
  on `Wake::Broken`, with the terminal restored as far as it still can be, and a
  non-zero exit. The check may sit around crossterm (for example a poll on stdin
  that looks for HUP before each `event::read`) or replace the source. It must
  not add a wall-clock timeout to the read path, because the frame has one clock
  and it is the pulse's (TASK-54bb5cddc671).

## Proof

Through the binary, per CLAUDE.md. Spawn `ank tui` on a pty, close the master,
and assert that the child exits by itself and is reaped. The guard against a
regression is that it exits at all. A test that only counts milliseconds would
measure the runner. The behaviour is OS-dependent and is not verified until it has
run on Linux, macOS and Windows.
