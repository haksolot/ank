 on every entity. Measured on TASK-3c12e0ced2c0, the first entity in this corpus to carry a machinery entry: version 4, one entry covering 2 to 3. Version 1 to 2 is the claim and 3 to 4 is the done, and neither writes an entry, by the decision TASK-3c12e0ced2c0 tested. So a naive version > last_to fires on the very first subject of the rule. The transitions cannot be counted either: claim and release each write the file and leave nothing durable behind, so a task claimed and released five times carries ten versions no reader can evidence. For an adr and a spec the count closes exactly, because the only non-entry writer is accept: ratified present is one write, status superseded is another, and both are fields. The accounting is therefore implemented where it can be proven and silent on a task, which is the window ADR-16813b3bcf37 was written for anyway. The remaining half is a task of its own.
