 HEAD's and not --all: a history can have several roots, and --all would let fetching somebody's unrelated branch change what this corpus is called, which is the same instability as a path wearing different clothes. Among HEAD's roots the oldest is taken, with --reverse so it is the first line rather than the last, because that is the commit the repository actually began at and it is deterministic. And a tree with no commits answers null rather than falling back to its path: a value derived from the path would change when the directory moves, which is the defect this field exists to remove, reintroduced for the one case that cannot be answered. Verified through the binary on this very repository: a second worktree answers 5a02985accabde1a7365a01db237a245097ab4ca, the same as the tree it was added from, and an unrelated corpus answers something else.
