Reported in https://github.com/haksolot/ank/issues/549. In a corpus with some history, `find ""` is mostly log entries and the cap hides every task, so the way to list the ids of the tasks, ADRs and specs is one `--type` per run. Repeating the flag looks like the answer, and the parser accepts it, but `--type` is declared non-repeatable, so `--type adr --type task` silently lists only tasks and the reverse only ADRs.

`--scope` on `new` already shows the shape: a `multi` flag in the verb table, read with `values`. Doing the same for `--type` on `find` keeps one way of naming several values, needs no comma syntax, and leaves a single `--type` exactly as it is.

What this task does not do: change what `find` lists when no `--type` is given. Hiding log rows from an empty query is a separate question about the default, and the issue leaves it to the maintainer.
