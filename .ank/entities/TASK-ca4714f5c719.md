Development happens on Windows. The delete-pending lock bug found in
TASK-244a842bc0cc would have gone unnoticed in a Linux CI — but the converse is
true as of today, and Unix bugs would ship to users with nobody seeing them. A
single development platform makes the matrix indispensable, not comfortable.

`blocked_by` here carries ordering and not a technical dependency: the CI would
already run as it is. The specification offers no other ordering primitive (§3),
and doing the CI right after the bootstrap avoids rewriting it at the moment the
CLI acquires its modules.

Nothing depends on this task: it blocks no other.
