Measured on 2026-08-20 with GIT_TRACE2_EVENT, after the batching tasks landed:
`ank check` costs 7.0 s, of which git is 4.9 s over 24 processes, and the
largest single item is `cat-file` at 2.58 s over five calls.

Those five calls read all 1018 entity files as the default branch carries them,
3.9 MB of markdown, to answer two questions:

- **does this checkout's corpus differ from the branch's**, which is a
  comparison and needs no content at all -- git already stores the object name
  of every blob in the tree, and `hash-object` is already computing the working
  tree's side of it, which is the 0.77 s on the line below;
- **is this task `done` on the branch**, which does need the bytes, but only for
  tasks, and only for the ones whose object name differs.

So the first question is being answered by moving the whole corpus, and the
second is being asked of every entity rather than of the few that moved.

**What must not change is the answer.** `corpus_drift` decides whether a reader
is looking at the corpus everybody else reads (ADR-47e2ac102f58), and `done_on`
decides whether a task finished on the branch or only in this tree -- the
distinction §7 exists for. A comparison that missed a difference would report a
diverged checkout as level, which is the one direction this must never be wrong
in.

Not measured yet, and worth measuring before choosing the shape: how the 2.58 s
splits between the two questions. The criterion asks for bytes and process
count rather than seconds, for the reason the batching tasks gave: a clock on
CI is not the same number twice, and the cost being removed is bytes moved.
