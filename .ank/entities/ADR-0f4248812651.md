GitHub #777. Planning produces proposals that turn out wrong before ratification; that is what the proposed state is for. Today such a proposal stays proposed forever, sits in the review queue, and a successor written with --supersedes cannot be accepted until the decision it replaces is ratified: the next command accept prints is to ratify the very decision being turned down.

Rejecting is given the authority of accept and not the authority of the author, because a proposal an agent can withdraw is a proposal an agent can make disappear before a human reads it; the record keeps it, as rejected, with the reason.

A ref and not only a status: everything else that settles a document is anchored where an editor of the file cannot reach (refs/ank/ratify/<id>), and a status line an agent could type is the one thing check could not tell from a decision.

The verb itself enters the surface through the supersession of ADR-376bed7fa39a. The new status is a value of the data model, and SPEC-ed5f09df66ef moves with it.
