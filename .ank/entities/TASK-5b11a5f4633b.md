Measured 2026-09-14 on this repository, binary of 74024e6, on a branch
where `ank archive` had moved the 1485 entities its dry run lists (1415
entries, 36 ADRs, 34 specs): `check` went from exit 0 to exit 8 with 17
faults, all of one shape: "created <date>, after ADR-52bb0da2023a was
ratified, and no entry about it carries a produced hash: no ank verb
wrote it", one per task done today. Their creation records are entries
whose subject is a task done on the default branch, so ADR-467ce7e9cda1
makes them cold and the verb moved them; the accounting check of
ADR-52bb0da2023a then read the hot entries only and found none.

TASK-25a56395cf73 made references, supersessions, blockers and log
subjects resolve against both roots; this is the same defect one step
further: an entity looking up its own entries. ADR-467ce7e9cda1 forbids
re-parsing an archived file in `check`, so the produced hash has to come
from what the index already holds for the archived entry (its title
carries "produced <hash>") or from a column added for it, and the rows are
read through Index::open_with_archive. The archive of this corpus waits on
this task: the hot corpus is 2048 files today and would be 563.
