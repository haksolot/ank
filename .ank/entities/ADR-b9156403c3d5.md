## Context

GitHub issue #385, reproduced on this tree at 0195eb1: a done task carrying a
scope entry git never knew (a typo, a bare directory where a glob was needed)
is a permanent fault. ADR-3094538d831e deliberately keeps that fault -- a death
git cannot explain must not be silenced -- but amend refuses every change to a
done task, so no verb can clear it. The only exit is editing
.ank/entities/<id>.md by hand, which works and is invisible: the guard holds
only the traceable path and pushes toward the untraceable one.

## The decision

The frozen field of a task is done_criteria, anchored in the claim and then in
the proof's criteria hash (ADR-6b3f19e08a24). scope is not that field: it
describes where the work happened, and correcting a description does not alter
what was proven. So amend distinguishes the two on a done task instead of
refusing wholesale.

The change is journalised exactly as every amend already is (LOG "amended:
+scope / -scope"), which is the recording issue #385's direction 1 asks for,
with no new verb to learn. A dedicated repair verb was rejected as a second
door doing amend's job for one rare case.

## What must not move

done_criteria after done. check replaying the proof's criteria hash on done
tasks (the companion task citing ADR-6b3f19e08a24) is what keeps this door
honest: scope opens because it is not anchored, the criterion stays shut
because it is.
