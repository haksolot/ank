Raised by TASK-530f27a4aeb3. Amends the last clause of ADR-aaee5307b34c, "a push whose stdout carries no status line for the ref keeps the ls-remote reading alone", and nothing else of it.

## What ank does today, measured

Measured 2026-10-25 through the binary (ank 0.9.2 at 8ba6558d, git 2.47.3), against a bare remote reached through a readable `remote.origin.url` and an unwritable `remote.origin.pushurl`; the full numbers are in the task's log. The raw `git push --porcelain` exits 128 with an empty stdout; `ls-remote` answers, and the ref equals the lease. TASK-530f27a4aeb3's body measured the same shape against GitHub with no credential helper (`could not read Username`, exit 128, no status line).

- `claim` exits 4 `held by <caller>`, naming the caller as the holder that blocks it, and keeps its local ref.
- `log` warns `taken over while logging` and fetches the remote record over the local write.
- `done` runs its verifiers, writes the task file `done`, then exits 4 `moved while it was being completed`, the ref left a claim.
- `release` prints `released` with no warning; the remote ref survives and the local one is put back.

Every one of these reads a lost race, and nobody won one: the ref is where the lease said it was.

## The decision

**The state already answers it.** ADR-aaee5307b34c classifies by state, and its own rule says a race is lost only when the remote ref differs from the witness. A failed push with the ref still equal to the witness is, by that rule, not a race. The no-status-line clause was written to keep older transports on the old reading; the old reading was the defect, and a push with no status line is exactly the one that never reached the remote's update: no report-status was ever sent, because the remote never got as far as receiving a command.

**So it is a refusal, with no reason to carry.** It has the consequences of a `remote rejected` refusal verb by verb, which ADR-aaee5307b34c already settled: `claim` exits 9 and unwinds its local ref, because a remote that refuses this clone's writes would refuse every task in turn; `log`, `done`, `release` and `close` keep their local write and exit 0 with a warning, so `done` completes locally as it does for an unreachable remote. Nobody is named as holder and nothing is fetched over the local write.

**The diagnosis is a command, not a reading of stderr.** There is no reason on stdout to print verbatim, and stderr stays unread (ADR-9307e5d214a7). What the warning or the error gives instead is the command that reproduces the failure where a human can read it: `git push --dry-run <remote> <refspec>`, which authenticates against the push URL and prints git's own diagnosis.

**What it does not change.** A push that fails while `ls-remote` fails too stays an unreachable remote. A ref differing from the witness stays a lost race, status line or not. The retry without a witness stays bound to a client-side `rejected (stale info)`. No verb, exit code or configuration is added.

Scope is the two files that carry it: the classification in `git.rs`, the verb-by-verb consequence in `claim.rs`.

Left to the maintainer: ratification.
