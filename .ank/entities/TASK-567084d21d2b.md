The last of ADR-5fbd99bf6fd5's offers, and the one that answers the question a
new reader actually has. Installing ank is easy. Knowing what to say to an agent
so that a repository with two years of history acquires a corpus worth having is
not, and it is nowhere written down.

**Three prompts, because the adoption has three moments**: state what the code
already decided as ADRs, so the constraints that exist implicitly become
readable; turn what is currently a list of intentions into tasks with scopes and
criteria; and check the result. A reader who pastes the first one gets something
they can judge, which is the point at which they decide whether the tool is for
them.

**The drift test is the substance of this task.** Prose duplicated in three files
diverges, and this particular prose is the one where divergence is worst: an
installer teaching a prompt that the documentation has since corrected. So the
criterion asks for character-for-character equality, asserted by a test, which
makes one of the three the source and the other two derived. Which one is the
source is an implementation choice; that there is exactly one is not.

Forty lines is the ceiling because ADR-5fbd99bf6fd5 refuses a wizard, and because
what does not fit on a screen after an install is not read.
