Measured on 2026-08-20: of the 7.0 s `ank check` costs, 2.09 s is ank's own
work and almost all of it is this. Every entity is read, parsed and serialised
back to compare against its canonical form -- 1018 of them, about 2 ms each.

That work is not wasted in principle: non-canonical form is a fault §4 requires
`check` to report. It is wasted in practice, because the answer for a file that
has not changed is the answer it gave last time, and the index already carries
`files (path, hash)` for exactly this kind of question.

**This is the third cache in this corpus and the least dangerous of the three**,
which is worth stating rather than leaving to be assumed. A stale signature
verdict claims an anchor that does not hold (TASK-dbef284a166c); a stale
canonical verdict, on the wrong side, claims a file is well-formed when it is
not -- so the key is the content hash and nothing else, and a hash that does not
match is a full inspection. There is no configuration to fold in, no keyring, no
allowlist: the input is the bytes, and the bytes are the key.

The criterion asks for the round trip -- edit, revert, edit again -- because
that is where a cache keyed on a hash is tempted by a mistake: a file reverted
to a previous state has a hash it has seen before, and the verdict for it is
the old verdict, which is correct here precisely because the input is the whole
content.
