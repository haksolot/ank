## Context

ADR-3094538d831e lowers the severity of a dead scope only where git can name
what killed it. For a path no commit ever carried it keeps the fault: the death
is one git cannot explain. A task's scope ahead of the code is already a
signal, "matches no file yet: work not started". An ADR's is not, so an ADR
cannot govern a file before the file exists.

Planning decides before the code, and ratification usually comes before the
implementation, so the corpus forces one of two bad shapes: a scope that lies
(a neighbouring file standing in for the one the decision governs, so
`ank context` on the new file never serves the rule), or a second signed act,
`accept --rescope`, for a decision that did not change. ADR-43cbb20dcbf1 met
it on its first `ank check`.

## Decision

The open task is the promise that the file will exist. While one covers the
path, the scope is awaited, not dead. When the last one ends without the file,
the fault comes back on its own and names the task that ended.

## Rejected

- Lenient while proposed, strict once accepted: the fault arrives at the
  ratification, which is exactly when a plan ratifies before it codes.
- A marker in the scope (`path?`, or a `planned_scope:` field): a format and
  contract change, and removing the marker once the file is born is one more
  signed write.
