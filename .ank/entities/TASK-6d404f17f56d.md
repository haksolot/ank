Implements ADR-493471d64ba0. Read it before starting: the category being added is
external attestation, durable but authored by no branch, and the reason it goes
in a ref rather than a file is that it has no tree to travel in.

Almost nothing here is new machinery. The record is a blob written the way a claim
record is written; the push is the same `--force-with-lease` compare-and-swap; the
refspec `init` installs already fetches `refs/ank/*`, so an existing repository
needs no configuration change. Reuse all of it rather than writing a parallel
path, and rename what currently says "claim" in those helpers so the shared code
does not lie about what it carries.

Read through the one coordination enumeration in `context.rs` that every listing
verb already shares. A second walk over the refs would be free to disagree with
the first, which is the failure this codebase avoids by construction elsewhere.

The union must be symmetric. Do not treat the file as authoritative and the ref as
a cache: between a `done` landing on a branch and its merge, the ref is the only
place the reference exists, and that window is most of a branch's life. A reader
preferring the file would show an unanchored task and emit a signal telling
somebody to attest work that is already attested.

Mark the origin in the display. A detached proof lives outside the tree and a
reader deciding how much weight to give it needs to know that without being told
to prefer either.

The pruning predicate is the one `done_on` already implements for completion
refs. Reuse it. A proof ref pruned on time would delete the record precisely
during the window it exists to cover.
