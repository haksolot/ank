Found in use, on 2026-08-22. `ank close TASK-da7738572825 --reason "..."` took a
reason naming `TASK-eb2c8b0bee45`, an identifier written before the task it
meant existed. The correction had nowhere to go: `ank log` answers `no task in
progress for this agent`, and a closed task cannot be claimed, so the closure
reason is wrong permanently and the correction had to be written on a different
entity where nobody reading the closure will find it.

**The model already has the answer and the surface does not reach it.**
ADR-25f977377fa0 says a correction is a new entry naming the one it corrects,
written once and never modified. Nothing about a settled task makes that untrue;
what stops it is a claim requirement that exists to arbitrate *work*, and there
is no work left to arbitrate on a task that is done or closed.

**An entry settles nothing, which is why this is safe.** The log anchors nothing
(ADR-ff294eff4d1a), no verb refuses on it, and writing one moves no frontmatter
and bumps no version. A closed task stays closed and a done task stays done with
its proof intact; what changes is that the record beside them can be corrected
by the next reader instead of standing wrong forever.

**What must not be built.** No reopening, no second transition, and no relaxing
of the claim requirement anywhere else: an open or in_progress task with no
claim is refused exactly as it is today, because there the claim is doing its
job.
