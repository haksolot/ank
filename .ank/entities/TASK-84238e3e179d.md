Raised at the start of the session that built the CLI, and it blocked three
separate things before being written down: no entity records who created it, so
two of §4's signals cannot be computed at all. A third needs `git log`, which
ADR-b8884edcebe3 forbids as porcelain -- that one stays out of scope here, and
is a limitation rather than a gap.

A format change, so ADR-63b59c5c26f7 fixes the order and it is not negotiable:
**specification first, then the goldens, then the code.** The field does not
exist until §3 describes it.

Two traps worth naming in advance. The parser uses `deny_unknown_fields`, so a
new field is a parse error for any *older* tool reading a newer file -- decide
what that means before writing it, not after. And the round-trip is
byte-identical on canonical form, which makes the field's position in the fixed
order part of the format rather than a detail: adding it changes every canonical
file, and the goldens are where that is settled.

The corpus in `.ank/` predates the field. A parser that refuses a file for
lacking it would make this task unable to read the repository it is being
developed in.

## Notes carried in the log

SCHEMA_VERSION is 2 and MIN_SCHEMA is 1, so the check is a range and no longer an equality. The asymmetry is the design: reading older is a promise (every field added after v1 is optional, absence means 'written before this existed'), reading newer is refused, because the fields a tool does not know are precisely the ones it would drop on the next rewrite. Refusing on the version is also the only diagnosis that helps -- deny_unknown_fields names a field where the file names a schema.

author omitted entirely when None rather than emitted empty: that is what lets a schema 1 file round-trip byte for byte through a tool that knows the field, and it is why the corpus needs no migration. Position between created and status is part of the format, not a detail, since canonical form is a fixed field order.

Ten struct literals across six files stopped compiling, which is what the scope correction was for. All take author: None -- test fixtures represent entities of unknown provenance, and inventing one would have made the burst tests pass for the wrong reason.

The two signals plus the aggregate. Burst uses a sliding window over sorted timestamps and reports the widest run rather than one finding per window, so a long burst stays one line. The self-blocking signal compares against the claim record's claimed timestamp, which already existed and needed nothing new. Tested with a negative case each: the same volume spread across a day is silent, and a blocker created before the claim is silent -- without those the tests would pass on any implementation that always fires.

tests/cli.rs is out of scope, so the 'ank new writes it' assertion lives in commands.rs and reads the bytes on disk rather than the returned model: a field set on the struct and dropped by the serializer would satisfy every in-memory check and leave nothing in the corpus.
