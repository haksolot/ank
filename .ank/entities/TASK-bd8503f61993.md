Found while running the suite for TASK-6f4ff66894d2, and pre-existing: verified failing at origin/main (2215a78) with the work stashed, so nothing in that task caused it.

The helper composes `file:///{path}` from a Windows path, giving `file:///C:/Users/.../ank-cli-it-NNNNN-0`. git 2.54.0.windows.1 reads that back as the path `/C:/Users/...` and reports 'does not appear to be a git repository'. The test therefore fails on the first clone, before it reaches anything it exists to assert. It is green on the Linux runner, which is why it landed: the platform rule this repository states -- OS-dependent behaviour is not verified until it has run on all three -- is exactly what this falls under, and here it is the *test harness* that is OS-dependent rather than the code under test.

The fix belongs in the helper and nowhere else. What it must not do is drop the shallow case on Windows: the third state of section 4, a history that cannot answer, has no other test.
