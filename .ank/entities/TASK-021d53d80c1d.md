Reported from a Windows machine: every hook ank installed failed with exit 127,
`/usr/bin/bash: line 1: \?\C:\Users\...\ank.exe: No such file or directory`.

Cause: `exe()` in hooks.rs writes `current_exe()` through `fs::canonicalize`,
which on Windows returns the verbatim form `\\?\C:\...`. Claude Code runs a hook
command with Git Bash, where `\\` inside double quotes collapses to `\`, and
backslashes are not path separators at all: the path reaching exec is not a file.

The suite did not see it because `ours()` in hooks_install.rs built its
expectation with the same `fs::canonicalize`, and nothing ran the command the
install wrote.
