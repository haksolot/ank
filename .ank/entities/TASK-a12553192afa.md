ADR-9e56318631f3 sorts four questions into two roots. This task is the sorting,
and nothing else: no new way to find a corpus, no declaration read from
anywhere, no behaviour that was not already reachable.

It is reachable today. `--repo <path>` already lets a caller stand in one tree
and address a corpus in another, so the detached case is not hypothetical and
does not wait for the resolution work. What is missing is the second half of
the address: which tree the corpus is anchored to. `--worktree <path>` is that
half, and its default is what keeps every existing layout intact, the umbrella
corpus of section 6 included: absent the flag, the work tree is the corpus
directory and the two roots are one, exactly as today.

**The falsification comes before the refactor.** Point `--repo` at a corpus in
one directory and `--worktree` at a checkout in another, then read what the
binary does with a scope glob, with `context <path>`, with a verifier and with
a `commit:` proof. Each of the four is expected to be wrong today in a
different way, and the four failures written down before any code moves are
what makes the assignment testable rather than argued.

Two of them are worth naming in advance because they fail quietly rather than
loudly. A scope glob confronted against a corpus directory matches nothing,
which is not an error but a dead scope, and ADR-3094538d831e makes a dead scope
a fault: a detached corpus would report every one of its own scopes as a fault.
And `commit:<sha>` is the one proof type checked against git, so a sha of the
code looked up in the corpus repository is not a weak proof but an unfindable
one.

**What must not be built here.** No search for a corpus, no reading of any file
outside the corpus, no change to what a caller who passes neither flag sees.
The goldens are the guard: a diff in one means the degenerate case moved, and
the degenerate case is every user there is today.
