Issue #499, reproduced on 96c7fd7: `git init -b main && ank init` exits 0 with
no word about the refspec, `git remote add origin <url>` then leaves only
`+refs/heads/*:refs/remotes/origin/*`, and neither `check` nor `status` notices.
Claims and completion refs are then never fetched, and nothing tells you. The
usual flow for a new repository (`git init`, `ank init`,
`gh repo create --source . --push`) hits it every time.

**Mind TASK-f067ae7c84ff.** The earlier fix is the reason init now skips when
there is no remote: writing `remote.origin.fetch` before the remote exists made
`git remote add origin` refuse with "remote origin already exists". Do not bring
that back. Reporting the missing refspec afterwards, where the state is visible,
is the route that cannot break it. Its test (tests/init_origin.rs) has to stay
green.

The refspec lives in `.git/config`, so a fresh clone never has it: that is the
second case the criterion names, and the same check covers it. Whether the
repair is `ank init` run again or a narrower command is left to the
implementation; whichever it is, `init`, `status` and `check` name the same one,
and `ank help init` says it.

Reading `.git/config` is a git call and not a corpus read, so `status` pays for
it within ADR-f3d1dea65d84 and ADR-9307e5d214a7; check the budget those two set
before adding a process.
