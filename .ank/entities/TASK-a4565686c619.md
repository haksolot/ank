The decision is ADR-1556aaffe0c5; this task is its mechanism. Measured 2026-09-14,
release build: `graph --json`, which opens the index and reads rows, costs
0.05 s at 960 entity files, 0.09 s at 1921, 0.16 s at 3842 -- the whole of
it is `Index::scan` (`index.rs:620`) reading and SHA-256ing every file.

**The predicate, stated once.** A file is hashed unless its (mtime_ns,
size, inode) equal the row's and its mtime is strictly older than the
index's last write. An unavailable field is a mismatch. The last write is
the mtime of `index.db` after the transaction commits, or a value taken
from the entities directory's clock, never wall time from a different
clock. The scan keeps its single `read_dir`; `std::fs::metadata` per entry
replaces `std::fs::read` on the steady state.

Schema bump: the `files` table changes shape, so `SCHEMA_VERSION` moves and
every index rebuilds once; on the same day as TASK-b646631fa10a that is a linear cost.
The `Refreshed` struct (`index.rs:299`) gains `hashed`, which is how the
criterion is counted and not timed.
