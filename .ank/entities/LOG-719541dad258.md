 TMPDIR: after ank init in a repository with no remote, .git/config carries includeIf hasconfig:remote.*.url:** pointing at .git/ank-origin.config, which holds remote.origin.fetch. Adding origin first: git remote add origin exits 0 and remote.origin.fetch carries +refs/ank/* and +refs/heads/*. Adding upstream first: git remote add upstream exits 0, then git remote add origin exits 3 'remote origin already exists' and remote.origin.fetch carries +refs/ank/* alone, so the refspec git would have written is lost too. The condition cannot be narrowed: git's only hasconfig form is remote.*.url, so any remote with a URL turns the include live. Moving the key to worktree scope does not hide it either -- extensions.worktreeConfig true with git config --worktree remote.origin.fetch, then remote add upstream, then remote add origin, still exits 3. So no config placement is visible to git fetch and invisible to git remote add, and the original criterion, which required remote add to succeed AND the ank refspec to be present the instant it returns, asks for something git does not offer. The criterion now asks for what is reachable and is worth more: git remote add origin works from every state ank init leaves, which is what status --remote already tells the reader to run.
