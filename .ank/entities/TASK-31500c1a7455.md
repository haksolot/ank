The first of the three things ADR-e39a44f80e0e requires, and the one the other
two rest on: an installer cannot place a binary the release never built.

**One job, one checkout, one version.** The two executables come out of the same
`cargo build` invocation because the alternative is versioning them apart, and a
generated passthrough built from an older table advertises verbs the installed
CLI does not dispatch. That is a refusal no exit code in section 4 describes, and
it is worth an explicit CI assertion rather than an assumption: the criterion
asks for the versions to be *shown equal*, on all three platforms, not for the
workflow to look as though it produces them equal.

The npm side is the fiddly half. The wrapper at `npm/ank/bin/ank` resolves a
platform package through `optionalDependencies` and spawns what it finds; a
second bin entry follows the same route to the same package, and must keep the
same exit-code passthrough, since section 4 gives 4, 6, 8 and 9 meanings a caller
branches on.
