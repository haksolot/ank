Measured on 2026-08-20: the two halves of this already disagree.

`check` has an advisory mode, documented and deliberate: with no key declared
it does not judge signatures at all, because there is no allowlist to judge
against. `accept` has none. It runs `git commit -S` unconditionally
(`human.rs:4319`) and exits 9 with `git config user.signingkey <key>` when that
fails, so a corpus running in the advisory mode §8 defines cannot produce a
ratification at all.

That is not a policy, it is an asymmetry nobody chose. This decision makes the
two halves agree, in the direction the threat model already points.

**The threat model is what permits this.** SPEC-199de7ac4730 argues the
signature from `$ANK_AGENT` being self-declared: an agent going off the rails
can call itself human, and only an external anchor stops it. That argument is
sound and is not withdrawn. But the same document states the boundary plainly:
"we protect against drift, not against an adversary." A signature nobody is
obliged to produce still anchors every ratification made by someone who does
produce one, and git itself has taken this shape for twenty years -- commits
are unsigned by default and nobody calls git's history unauthenticated.

**What must not degrade is the corpus saying which regime it is in.** An
optional signature is honest; a corpus that reads as ratified-and-verified when
nothing verified it is not. This is the same rule §8 already applies to the
fourth outcome -- signature present, no local public key -- which is a signal
and never a pass, on the grounds that a verification degrading to success is
not a verification. The regime is a fact about the corpus and belongs beside
the ratification queue, which is where `review` already names who may ratify
(TASK-8a80b590b356).

**The consequence to pay, and it is not small.** "Ratification requires a
signed commit" is in the body of SPEC-199de7ac4730, and the body of an accepted
spec is hashed into its ratification commit (§3). So this decision cannot be
amended into the specification: it needs a succession, written against the
behaviour once it exists rather than before, and ratified by a human. The last
signed ratification this corpus needs will be the one that makes signing
optional.

**Not in scope.** The coordination plane stays in git refs (ADR-4e7c25b1f639),
and the anchor stays a commit. What changes is whether that commit carries a
signature, never where it lives.
