The human listing of `find` marks every row from the coordination plane, and its
`--json` emits the stored status alone. So the two surfaces of one verb answer
differently about the same row: a reader at a terminal sees `[finished:<sha> on
<branch>]`, and a script sees `open`. A caller that filtered on the JSON would
schedule work already done on a branch, which is the window the completion ref
exists to close, reopened for whoever automated the question.

ADR-0c8ab846d262 is the argument. Colour depends on the reader; structure does
not. A marker is not colour: it is the answer, and it reads the same in a pipe.

`context --json` already carries the field, on a key beside the stored status
and with the brackets stripped. That is the shape to reuse, not a second one:
two spellings of one state would be the divergence this task exists to remove,
moved down a level.

Additive, so no consumer breaks: the stored status stays where it is, under the
key it already has.
