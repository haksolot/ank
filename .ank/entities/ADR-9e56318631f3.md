  A corpus is anchored to a work tree and located in a directory, and the two are separate facts a verb resolves separately. What is confronted with the filesystem resolves against the work tree: a scope glob, a path handed to context or scope, the working directory of a verifier, and the commit a commit: proof names. SPEC-201041998d90 describes one root, and the tool carries one field for it:
`Repo` holds `root`, and `.ank/` is the directory it walked to. That single
value is asked four different questions. Until now the answers agreed, because
the directory holding the code and the directory holding the corpus were the
same directory.

They are not the same question, and TASK-2f01baf94632 already measured the day
they part. Its finding is exact and worth quoting rather than paraphrasing:
claims are refs, so they land in the git repository of the resolved root and
never in the one holding the code being changed, and "the coordination plane
and the code part company, silently". That task closed by naming the resolved
root and warning when the two differ. That is the right answer for an accident.
It is not an answer for a corpus a reader put elsewhere on purpose.

**Four questions, and they sort cleanly into two roots.**

The work tree is what the filesystem is asked about:

- **Scope globs.** Section 3 says scope is the only attachment because a glob
  is confronted with the filesystem, where a label is confronted with somebody
  remembering it. A glob confronted against a corpus directory holding nothing
  but `entities/` matches nothing, and a scope matching nothing is a dead scope,
  which ADR-3094538d831e makes a fault. Every scope in a detached corpus would
  be dead on arrival.
- **A path handed to `context` or `scope`.** The caller names a file of the
  code. `context.rs` strips the root off it to answer; stripping the corpus
  root off a path in the code yields nothing.
- **A verifier's working directory.** `done` runs the declared command in the
  resolved root. `cargo test` in a directory of markdown files is not a failing
  test, it is a category error.
- **The commit a `commit:` proof names.** This is the one the code already
  states out loud: `commit:<sha>` is "the one type Ank checks against git", and
  the sha is a commit of the code. Resolved in the corpus repository it is not
  a weak proof, it is a proof that cannot be looked up at all.

The corpus directory is what git is asked about on the corpus's behalf:

- **`refs/ank/*`.** ADR-4e7c25b1f639 puts claims in refs and ADR-a1de673043b4
  keeps them per repository so that nothing is arbitrated across a boundary the
  refs cannot reach. The boundary that matters is the corpus: whoever shares the
  corpus is whoever arbitrates over its tasks.
- **The corpus's drift from its default branch.** ADR-47e2ac102f58 says every
  verb answers about the corpus in the working tree and names the gap with the
  default branch. It keeps its full meaning here, read of the corpus's own
  checkout, which is the thing it was always about.
- **Every entity path handed to git**, which comes from the store and never
  from a literal, and the store is rooted in the corpus.

**Why this is a decision and not a refactor.** Nothing above changes what any
verb answers today, because today the two roots are one directory and the
degenerate case must stay byte for byte what it was. What changes is that the
assignment stops being an accident of there being only one value to reach for.
Written down, it is a rule a later verb is held to; left implicit, the next
person to add a git call picks whichever root is in scope and the two planes
part company again, silently, exactly as TASK-2f01baf94632 recorded.

**What makes them diverge, and what does not.** A verb never infers a
detachment. `--repo` names a corpus and nothing else, which is what keeps
the layout section 6 describes as usable actually usable: a single `.ank/`
standing above several checkouts, with scopes written `repoA/src/**`, is a
corpus whose work tree is its own directory, and a rule reading the work
tree off the caller's current directory would kill that layout without
anybody deciding to. So the work tree is the corpus directory until
something says otherwise, and the something is explicit: a flag on the
invocation, or the declaration of ADR-96174f1ac2b7. That is also what makes
this decision provable on its own, before any declared resolution exists:
the binary is driven with both roots named and the assignment above is
read off its answers.

**What this does not decide.** Where a corpus may live, and how a reader finds
one that is not in the tree, is a separate question and a separate decision.
This one holds even if no corpus is ever detached: it is what makes the outer
corpus of section 6 describable rather than merely warned about.
