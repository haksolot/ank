Measured on 2026-09-20 with the binary built at 8310e75, in a throwaway corpus:

    claim ref before: expires: 2026-09-20T18:36:04Z
    remote ank refs: []
    $ ank log "hello"
    warning: TASK-3365909b0529 was taken over while logging, the claim was not renewed
    logged LOG-5b6b3d1b2e32 on TASK-3365909b0529
    claim ref after:  holder: tool/1.0
                      expires: 2026-09-20T18:36:06Z

Both halves of that sentence are false. The holder did not change, and the
lease did move, by the two seconds the reproduction slept. `ank status`
agreed: `{'id': 'TASK-3365909b0529', 'expires': '2026-09-20T18:36:06Z',
'lapsed': False}`.

The trigger is a remote that carries no copy of the claim ref while the local
`remote.origin.fetch` carries `+refs/ank/*:refs/ank/*`, which `ank init`
writes. With no remote at all, or with a remote that has the ref, `log` is
silent and correct. `claim::renew` comes back `Cas::Lost`
(crates/ank-cli/src/commands.rs:2303), and an absent remote ref is being read
as somebody else's write rather than as nothing to compare against.

This is not cosmetic in the parallel case this repository runs on: a claim
whose push did not reach origin makes every `ank log` of the holder report a
takeover that did not happen, and the entry after it is written anyway, so an
agent reading its own warnings is told to release a task it still holds.

Found while working TASK-58f946514828, whose scope is docs/integrating.md and
docs/agents.md, so it was recorded rather than fixed. The same fetch decides
where a warning lands, which that task documents: under `--json` this one
reaches the `warnings` array rather than stderr, because `warn_before_acting`
returns early and `report_logged` concatenates it into the document.
