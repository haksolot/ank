The request came from a reader working in repositories owned by teams that have
their own workflow, whose requirement was stated plainly: leave no traces. He
proposed resolving the corpus under a directory named by the slugified git
remote URL, falling back to the repository root when that directory does not
exist.

The need is real and the corpus already agrees with most of it. The key is the
part to refuse.

**Declared, never discovered, is already settled.** ADR-621a7fd96ce1 says
aggregation is declared and nothing walks a filesystem looking for corpora, and
ADR-a1de673043b4 says a peer is a key in a file and only that, because
inference is how a corpus starts depending on where somebody happened to check
something out. A directory looked up by convention and used if present is that
inference wearing a different hat: the corpus in effect would depend on what
exists on one laptop. So the location is a declaration, and a declaration that
is absent means the walk, not a search.

**The identity is settled too, and it is not the slug.** ADR-621a7fd96ce1
requires an identity "derived from its root commit and never from its path", and
TASK-d55cef0b0ef1 already shipped it and put it in `ank status --json`. A
remote URL fails the same test the path failed, and fails it in more ways: one
clone over ssh and one over https key differently, a fork keys differently from
its upstream, a rename on the forge silently orphans the declaration, and a
repository with no remote has no key at all. The root commit moves for none of
those. What the slug buys is that a human can type it, which is a question for
the verb that writes the map, not for the map.

**Where the declaration lives is what makes the promise keepable.** A pointer
committed in the code repository would be the more useful design for a team
that wants shared context outside its code, and it is precisely the trace the
request refuses. So the map is outside the repository, one entry per repository
identity, and the code repository keeps not one byte it did not already have.
Worth stating, because it is the half a reader discovers late: `.ank/` merely
gitignored still leaves refs, since `claim` pushes `refs/ank/claims/<id>` as
soon as a remote exists. Under this decision those refs go to the corpus, which
is what ADR-9e56318631f3 assigns, so the team's remote stays untouched for real
and not only in the working tree.

**Precedence is the declaration, and it is never silent.** A map entry is the
caller saying which corpus they mean, which is what section 6 already grants
`--repo` when it short-circuits the walk without contradicting it. The cost of
that choice is the failure section 6 spends four bullets guarding against: a
`.ank/` appearing in the tree later would be ignored without a word. The answer
is the one already built for the same shape of problem: both roots named on
standard error, on standard error precisely so `--json` stays byte for byte
what a parser reads, silenced by `--quiet`, degrading and never failing.

**What must not be built.** No derivation of a location from a remote, a path
or a slug. No search of any directory for a corpus that was not named. No
writing across a corpus boundary, unchanged from ADR-a1de673043b4. And no new
third-party crate: `ank-cli` declares one real dependency and says why in its
manifest, so resolving a home directory is done with the environment and the
standard library or it is not done.
