`.ank/config.yml` gained `default: true` under two verifiers on 2026-08-30
(ADR-443590981e41). Every released `ank` now refuses this repository:

    $ ank find --status open
    error[1]: .ank/config.yml: verifiers.cargo-test: unknown field `default`,
              expected `run` or `timeout` at line 9 column 5

Measured the same minute: `ank` 0.6.0 on PATH exits 1 on every verb, and the
same tree built from source answers `check: ok`. The binary is old; the message
blames the file.

## The rule already exists, one file over

`docs/format.md` legislates this exact case for entities:

> Newer is refused, and refused **on the version rather than on the first field
> it does not recognise**. Since unknown fields are rejected, a tool that
> checked only its own version would report a file one version newer as
> *unknown field `author`*, and its reader would go hunting for a typo. Naming
> the version says the one true thing: this file is newer than this tool.

`config.yml` carries `schema:` for that purpose and never gets to use it:
`deny_unknown_fields` on `ConfigFile` fires during deserialization, before any
version is compared. So the config reader produces precisely the message the
format policy exists to prevent, and the reader it misleads goes hunting for a
typo in a file that has none.

## What this cannot fix

0.6.0 is shipped and its parser is field-first: nothing written here reaches it,
and a corpus that declares `default:` stays unreadable to it until the reader
upgrades. That is not a reason to leave the next one broken. The value is that
`schema` starts meaning something before the next key is added, and that the
refusal names the version from then on.

Whether `.ank/config.yml` should also declare a higher `schema` is part of this
task and not settled here: bumping it helps no released binary, and leaving it
at 1 means a file carrying a version-2 key claims version 1. Decide it, state
the reasoning in an `ank log`, and make the reader agree with whatever is
chosen.

## Where the test goes

`crates/ank-cli/tests/schema.rs`, its own file. `tests/cli.rs` is inside
TASK-4aac's scope and that task is being worked in parallel; two agents in one
file is the collision the scope rules exist to prevent.
