`status.rs` already builds the list of claims held by other identities and prints
them under `elsewhere`, with the id, the holder and the expiry. Two things are
missing before that answers the question a reader actually has.

The title. The rows carrying it are already loaded in the same function, so this
is a join that costs nothing, and without it the reader has an id and must run
`show` once per claim to learn what anybody is doing.

The remote. `status` reads local refs only, and specification section 7 is
deliberate about that — `claim` is the one verb that pays for the network, and
every other verb describes the plane it has. That default stays. What is added is
an explicit opt-in, because on a parc of clones the local plane is not a smaller
truth, it is a different one, and a status that cannot say so is misleading
precisely when several agents are running.

Use `ls_remote` on the claims namespace; it is already there and already used to
disambiguate a refused push. Do not fetch: reading is enough to answer, and
writing refs into this clone as a side effect of a status call would be a reader
sanitising the plane underneath everyone else.

Mark what came from the remote. A claim seen only on origin and a claim seen here
are different facts and the line has to distinguish them, or the flag makes the
output more confident without making it more informative.
