Seen twice on 2026-10-23, on PRs #666 and #667: the step pipes https://get.nexte.st/<version>/mac into tar -C "$HOME/.cargo/bin", and on some macos-26-arm64 runners that directory does not exist, so tar fails and curl reports a write failure (exit 56). The same image passed on the rerun of 39967727022, so the directory's presence varies across runners of one image; the versions step printed rustc 1.99.1 and cargo 1.99.1 on the failing runner, so a toolchain is there, somewhere. Measure where before choosing the fix: a mkdir -p alone makes the binary land, and cargo only finds cargo-nextest if that directory is on PATH or is CARGO_HOME/bin.
