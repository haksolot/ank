The ratification of SPEC-20357e21a45a (TASK-8108e3771ba0, ADR-8bd76e8d7c4e) broke a succession that two source comments still name. `amend --reference` carried every entity that cited the predecessor, and every entity followed. Prose inside a source file is outside that mechanism by design: ADR-1e6bcbf62e61 makes an identifier written in prose a signal and never a reference the CLI rewrites.

**So the repair is a reading, not a substitution.** `verbs.rs:331` states a rule and cites the document that states it for every verb at once, and that document is SPEC-20357e21a45a today. `tests/cli.rs:19913` is about what ratifying the predecessor once found, which is history, and history is what `ank show` serves -- so that citation may go rather than move. The test allows both ways out. Which one each line takes is a reading of what its sentence claims, and that is the whole of this task.

**The gap is worth naming, because it is not a defect in the work that exposed it.** TASK-8108e3771ba0's criterion required every *document* citing the predecessor to follow through `amend --reference`, and every document did. Source comments are not documents, the suite was green when that task landed, and it was the signed `accept` -- a human act, deliberately later, and the whole point of the two-signature order ADR-8bd76e8d7c4e priced -- that turned these two stale.
