Section 3 says it in one sentence: any kind may carry a log, and a missing log
file means no entry, never an error. The address is computed from the id, so
`.ank/log/ADR-<id>.md` needs no lookup and no new field. `store.log_path_of`
already builds it from an id alone, and `store.log_of` already reads it for any
loaded entity.

The CLI contradicts it. Both halves of the verb refuse a non-task by name, so an
ADR cannot be annotated at all. The refusal is older than ADR-ff294eff4d1a and
was correct when the log lived in a task body, which is a section the ADR
schema does not have. It stopped being correct when the log moved into a file
of its own, and nothing removed it.

Two places need care.

The `LogHome::Body` arm of the write path reconstructs an `Entity::Task` to
write the body back. That arm exists only for corpora predating the move, and no
ADR ever had a body log, so an ADR is always `LogHome::File`. Make that a fact
the code states rather than one it assumes.

Renewal. `log` renews a claim by working, and an ADR is not claimable. The
renewal must not fire, and it must not fail loudly either: nothing was held, so
nothing was lost.

`show` already prints the log only when it lives in a file, which is the
behaviour an ADR wants without any change.
