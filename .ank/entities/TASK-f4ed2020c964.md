Found while executing TASK-97437c25ddda, whose measurement pointed GIT_CONFIG_GLOBAL at a config with gpg.program set to a path that does not exist -- the stand-in for a machine where GnuPG is not installed.

The unit test this_repositorys_own_ratifications_are_signed then failed with 'ADR-01b6dd05f0db: Absent'. Its own comment says which outcomes are correct and why: 'Trusted on a machine holding the public key, Unchecked on one that does not -- CI, for instance. What must never appear is a verdict claiming the corpus is forged.' Absent is that verdict in its quietest form. It does not say the signature is bad; it says there is none, which is a stronger and more wrong claim than admitting the machine cannot tell.

The failure mode is narrow but real. CI never reaches it, because actions/checkout clones shallow and rev-list reaches no ratification commit, so every ADR is already the unverifiable case. It bites a contributor with a full clone and no GnuPG installed, or with gpg.program pointing at a binary that has moved -- and what they would be told is that the constraints of this repository are unratified.

The distinction matters more here than the wording suggests. Ratification is the only hard authority line in ank (ADR-c656cbcc33a9): a signed commit is what makes a constraint binding. Reporting an unverifiable signature as no signature at all reads, to an agent or a human, as a corpus nobody stands behind. The freeze already has a name for 'I cannot tell', and it should be used.

## Notes carried in the log

The object is not ambiguous, so the object decides. commit_carries_signature reads the commit with cat-file and looks for a gpgsig header among the headers, stopping at the first blank line; cat-file needs no gpg, no keyring and holds no opinion, and it is allowed plumbing under ADR-b8884edcebe3. classify_signature takes the bit as a third argument and stays pure: N with a header is Unchecked, N without one is Absent. Asked only on N, since every other status already says whether a signature was there. A cat-file that fails reads as false, which can only weaken Unchecked back to Absent -- the verdict the caller would have reached anyway -- and Unreadable already covers a git that cannot answer at all.

Two tests. The pure one gains the second N case beside the first, so the two verdicts sit on the same letter one line apart. The end-to-end one drives the OpenPGP path with no gpg anywhere in the fixture: the gpgsig header is written onto the commit object with hash-object and main is moved onto it, and gpg.program is pointed at a path that cannot exist. It runs identically on a maintainer's machine and on a runner that has never held a key.

Two obstacles worth recording. The first attempt asserted the control and the case in one repository, and the control passed while the case failed with Absent even though HEAD carried the header: ratification_at memoises per repository and id for the life of the process, on the sound assumption that history does not change under a running tool. Rewriting the commit after asking measured the memo. Two fixtures, one per state, and the reason is written beside them.

The second: a Rust string continuation eats the newline and the following indentation, which is exactly what the continuation lines of an armoured signature are made of. The block is built so the leading space of each line survives.

Confirmation beyond the new test: the whole workspace is green under a gpg.program that cannot be spawned -- 386 tests -- including human::tests::this_repositorys_own_ratifications_are_signed, the dogfooding test that found this defect. It failed there with 'ADR-01b6dd05f0db: Absent'; it now gets Unchecked, which is one of the two answers its own comment says are correct.
