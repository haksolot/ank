TASK-69e774ef9d64 closed green on Linux, and its first macOS run (PR #731, run 40712339509, job 122900734080) failed: `terminal::a_reader_whose_terminal_hangs_up_ends_by_itself` was still running at its 30 s deadline. 1757 of 1758 tests passed, and Windows passed its ConPTY test.

Hypothesis: macOS `poll(2)` does not support devices (see BUGS in the man page). It answers POLLNVAL for a tty, and `term::hangup` treats POLLNVAL as "cannot watch" and returns, so nothing is watched. rustix's `kevent` and `select` are both `unsafe`, which ank-tui's src forbids. mio's `Poll` + `SourceFd` is safe and is what crossterm already reads this terminal with on macOS (kqueue). It reports a hang-up as `is_read_closed`: EV_EOF on kqueue, EPOLLHUP or EPOLLRDHUP on epoll. So the watcher moves to mio and rustix leaves.
