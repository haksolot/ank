Measured on 2026-08-20, and this is the number that makes the question worth
asking at all.

A git process costs, from the caller's side on this machine:

    git --version        146 ms
    git rev-parse HEAD   111 ms
    git cat-file -p HEAD 153 ms

`git --version` does nothing and costs 146 ms. That is `CreateProcess`, loading
`git.exe` and its libraries, and whatever a virus scanner does in between.
`GIT_TRACE2_EVENT` does not show it: it measures git from inside git, so it
begins after that cost has been paid.

At roughly 120 ms a call and 24 calls, **process startup is 2.5 to 3 s of the
4.9 s `check` spends in git**, and the largest single item on the whole
profile. An earlier estimate in this corpus put the ceiling at 1.9 s; it was
taken from the trace and was therefore too low.

**The asymmetry is the subject, not a footnote.** A git process costs about
5 ms on Linux, so the same change buys almost nothing in CI and a great deal on
a Windows workstation. A decision taken on this repository's own numbers would
be a decision taken on the maintainer's machine, which is exactly why the
criterion asks for three platforms.

**What this task must not do is decide.** ADR-9307e5d214a7 is accepted and says
the plumbing goes through the git binary and never through a library; changing
it is a succession and a human signature. The argument that put it there is
about signing (ADR-92b9cda9f6a9): producing and verifying a signed commit is
three lines with the binary and would be, through a library, "at best
equivalent and at worst subtly different from what the user will check by
hand." That argument survives whatever this measures, because signing is not
what would move -- reads are.

So the shape a later ADR would take is already visible: reads through the
library, writes and every signature verdict through the binary, and the library
restricted to questions with no interpretation -- the bytes of an object, the
target of a ref. What is missing is whether it is worth it, and only running
code answers that.

**Measure the open separately from the reads.** A library that opens a
repository in 300 ms has given back most of what it saved, and an average over
one call would hide it.
