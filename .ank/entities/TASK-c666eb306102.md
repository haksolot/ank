Issue #502, reproduced on 96c7fd7 before this task was written: in a corpus A
declaring `peers.bb ../b`, `ank scope bb:does/not/exist.txt` lists the ADRs
scoped `**`, and so does `ank scope zz:whatever`, where `zz` is declared
nowhere. A local glob is matched against the peer-qualified path as if it were a
path of this tree.

§7 and `repo::peer_ref` say the `<peer>:<glob>` form is "the only thing that
crosses". So this is a defect and not a policy, and declaring a peer must not
silently widen every existing `**` entity.

The shared matcher is `context::in_perimeter`, used by `commands::scope` and by
`context`; start from there. The issue also asks that `scope` say when a peer
path does not exist. That is not part of this criterion: `commands::scope`
states that "the filesystem is never consulted, and a path that does not exist
yet resolves like any other", and that holds on either side of a peer boundary.
