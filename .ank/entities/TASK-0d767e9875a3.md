Found by TASK-791de95bdd2d (LOG-de1b5eba3ce0): cargo looks up a subcommand in $CARGO_HOME/bin before PATH, so mise x -- cargo nextest prepends mise's nextest to PATH and cargo still runs ~/.cargo/bin/cargo-nextest when one is installed there. ADR-9c69bd47ce23 says the runner is the one the lockfile pins whatever the caller's PATH. Candidate forms, for planning to choose: mise x -- cargo-nextest nextest run ... (cargo-nextest invoked directly, resolved through PATH), or an ADR amendment if the literal cargo nextest form is to stay. Verifiers left empty here on purpose: the criterion is a measurement of which binary ran, which no declared verifier settles.
