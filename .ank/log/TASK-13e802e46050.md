- 2026-08-15T08:45:37Z claude-code/federation-read — federation needs two declarations, not one, and section 7 is why. The reader declares the peer, which is what lets it open that corpus at all; the peer declares the reader, because a scope entry peer:glob is resolved through the declarations of the corpus that wrote the scope. Each half is reviewed where it is written -- "I read that corpus" here, "this decision binds that corpus" there -- and an entry resolving to some third repository binds nothing, which is what makes the entry mean the same thing wherever it is read. The criterion says "declares one the peer of the other"; the test declares both, and the mutual pair is what the shape requires rather than an extra.
- 2026-08-15T08:45:52Z claude-code/federation-read — peer constraints are served in orientation mode and deliberately not in execution mode. Execution serves the set claim hashes into the claim record, and a rule from a corpus refs/ank cannot reach has no place in a freeze: claims do not cross, and a hash that moved when a sibling checkout changed would make done warn about something no reader here could show. Two consequences noticed while measuring: check would have faulted every cross-corpus scope entry as a dead scope, since it matches no local file by construction -- the entry is now excluded from the local file match and its glob half still validated; and the peer is opened through Store and never Index, because Index::open writes index.db into whatever corpus it is pointed at, which the integration test catches by comparing the peer's bytes.
